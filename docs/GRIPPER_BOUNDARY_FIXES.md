# 그리퍼 경계 보완

## 수정 계획

1. 실제 기록의 qpos를 사용하는 회귀 테스트를 먼저 실패시킨다.
2. 명령 범위와 관측 범위를 명시적으로 분리한다. 기존 명령 좌표,
   체크포인트 출력 범위, 원시 관측값은 변경하지 않는다.
3. 미재현 감사에 누락·이전·모순 관측을 넣는 회귀 테스트를 먼저
   실패시킨 뒤, 관측과 전송 후 상태의 연결 검증을 공통화한다.
4. 관련 테스트, 정적 검사, 독립 코드 리뷰와 기존 아티팩트 해시로 검증한다.

통합 검토에서 `ExecutabilityTrace`가 관측 여유도에도 명령 범위를 적용해
정상 관측을 실패로 판정하는 연결 누락을 확인했다. 같은 경계 분리를
관측 여유도 계산과 두 MuJoCo 의미 평가 진입점에도 전달하고 회귀 검증한다.

## 경계 계약

`safety.joint_lower/upper`는 명령 범위로 유지한다. 선택적인
`observation_joint_lower/upper`가 없으면 관측에도 기존 범위를 적용한다.
두 관측 필드는 함께 지정해야 한다. MuJoCo 기본 설정만 그리퍼의 물리
관절 하한을 기존 canonical 좌표로 변환한 값으로 명시한다.
팔 관절의 기존 보수적인 범위와 하드웨어 기본 설정은 유지한다.

MuJoCo 그리퍼 명령 `0..100`의 변환식은 바꾸지 않는다. 관측값은
클리핑하지 않으며, 네이티브 물리 범위 위반은 float32 변환 전에 차단한다.
안전 평가가 허용한 출력도 명령 범위와 틱당 최대 이동량을 지켜야 한다.

평가 기록의 관측 여유도만 관측 범위를 사용한다. 명시적인 관측 경계는
안전 검사와 같은 float32 값으로 맞춘 뒤 여유도를 계산한다. 명령 여유도의
기존 float64 계산과 보고서 스키마·엄격한 검증 조건은 유지한다.

기존 설정의 해시를 보존하기 위해 새 관측 필드가 모두 미지정이면
해시 입력에서 그 두 필드만 제외한다. 명시적인 관측 범위는 해시에
포함되므로 새 MuJoCo 설정은 별도 실험 조건이며 기존 인증을 재사용하지 않는다.
이 호환성 보장은 프로젝트 설정 해시·fingerprint에 한정한다. `asdict`로
새로 직렬화한 전체 보고서 바이트가 이전과 같다는 뜻은 아니다.

사용자 지정 모델은 해당 모델에 맞는 관측 범위를 명시해야 한다.
지정하지 않은 기존 설정은 자동 확장되지 않고 이전처럼 엄격하게 동작한다.

## 진단 감사

재현 여부와 관계없이 후속 관측의 네이티브 상태는 `after_send`와 일치해야
한다. canonical 값과 관측 벡터도 일치해야 하며, 관측 시각은 유한한
비음수이고 전송 시각·이전 관측보다 뒤여야 한다. 예산 종료 시 요청이
참조한 관측, 안전 거절 시 거절 행의 관측·시각도 같은 기록에 연결한다.

## 증거 보존

`runs/gripper_boundary_diagnostic_001/`는 수정하거나 재실행하지 않는다.
이전 진단은 이전 소스와 설정에 관한 증거다. 현재 소스의 성능이나
새 설정의 과제 성공을 증명하지 않는다.

수정 전 소스·설정 사본은 무시된 로컬 경로
`runs/gripper_boundary_fix_001/baseline/`에 보관했다. 이 자료와 당시 Git 이력은
공개 저장소에 포함하지 않는다. 이번 수정은 활성 소스를 갱신하므로
동결 프로토콜의 소스 해시와 현재 소스가 같다는 주장은 하지 않는다.
